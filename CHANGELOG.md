# Changelog

All notable changes to this prototype. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

The v0.1 to v0.5 history below was developed as a local worklog and imported into this repository in a single commit (c0453dd, 2026-09-03), so those versions carry no individual release dates. Benchmark tables attached to a version are the numbers measured at that time, on the environment stated next to each table; they are kept as a historical record and are superseded by the current table in the [README](README.md#benchmarks).

## [Unreleased]

### Changed

- The zod4 line keeps the CoW path under an async container-level `.refine` (#13). `checksAreCowSafe` and `wrapperChecksAreCowSafe` accept a `.refine` predicate whether it is sync or async, so an object, array, tuple, record, map or set carrying one, an optional / nullable layer above a container (#56) and a union with a container option (#58) keep their skeleton instead of becoming a runtime island that copied the input on every parse; a union with an async option still takes the official product. `containerChecksFn` becomes an async subroutine on stock's schedule when a predicate is async: stock's `runChecks` calls every check synchronously in declaration order and only chains the awaits, so every predicate is called before the first `await`, a length / size check keeps its place, the results are settled in order at the end (a `false` does not stop the settlement of the later ones, a rejection throws at its position), and a length / size check that fails after a predicate was started settles the started ones first, so no rejecting promise is left unattached; the call sites of the six container skeletons, the union skeleton and the wrapper layers emit `await`. One exception to "every predicate is called" (third review of #76): stock's `runChecks` tracks its abort state synchronously until a check returns a promise, so an `abort: true` predicate that fails synchronously while no promise has started skips every later check without a `when`; the subroutine returns `INVALID` there instead of starting the later predicates (the predicate stock never calls is never called, and a rejecting one no longer turns `safeParseAsync` into a rejection), decides at runtime whether a plain-function predicate returned a promise, and keeps starting everything once a promise has started, as stock then defers the abort into its chain. Found on the way: `checksAreCowSafe` never listed record among the containers, so a record with any check, a sync `.refine` included, took the official parser and copied every parse; record is listed now (it has no length or size check, so only predicates reach its skeleton). The differential fuzzer already attached sync and async refines to containers, wrappers and unions; at the default 20 000 cases every case agrees with stock and top-level sharing among successful cases is 82.8% (default) and 83.7% (`"ignore"`), from 81.4% and 81.9%. New smoke assertions: every container, a wrapped container and a union share the clean input under an async refine, the dirty path hands the copy to the predicate, failure parity with stock, the predicate schedule against stock's own log, and a rejecting predicate after a failing one or a failing length check surfacing as the thrown error with nothing reaching `unhandledRejection`; an aborting sync failure before any promise skips the later async and sync predicates like stock (on an array and above an `optional(object)`), a passing `abort: true` predicate changes nothing, and after an async function or a plain function that returned a promise the same aborting failure starts the later predicate like stock.
- The async layouts of the zod4 array and tuple skeletons (#71) no longer read the input after their `await Promise.all` (#77, found in the review of #76). A child may mutate the input before its promise settles, and stock reads every element once before any promise settles (`$ZodArray` sizes its output with the length it read before its loop, `$ZodTuple` reads each fixed slot and takes `input.slice(items.length)` up front), while the copy path rebuilt the clean prefix from the live input, sized the copy and bounded the loops by the live length and decided a hole with a live `Object.hasOwn`, so `["a", "b"]` under a transform that wrote `input[0] = "MUT"` before settling came back as `["MUT", "b!"]` against stock's `["a", "b!"]`. The array skeleton now takes the length before its loop, captures each read and each hole in the first pass and rebuilds the prefix from the captured reads; the tuple skeleton does the same for its fixed slots and takes stock's `input.slice(items.length)` after the fixed slots started and before any rest product runs, so it starts every rest element from the slice and decides a rest hole on it (the second review found it reading and running each rest element in one loop, where a sync rest callback that wrote a later rest slot was observed and stock's slice is not), and keeps its presence guards on the live length, as stock's `handleTupleResults` decides presence after the await. The sync layouts keep their single pass and their documented second read (#36); the sync tuple layout still reads each rest element right before running it, tracked in #78. Smoke: the prefix rebuild, a push and a truncation after the await, and a hole filled after the await, for an array, a tuple and a tuple with an async rest (the last against the dense output, since stock's async rest is the sparse-array quirk the README declines to match); under an async fixed slot, a sync rest element that overwrites a later rest slot, a fixed slot that overwrites a rest slot before the slice and a rest hole filled by an earlier rest element. The differential fuzzer cannot carry this case: it hands one input object to both sides and fails any case whose input was mutated.
- The zod3 line's object, array and tuple skeletons are generated per schema (`packages/zod-cow-v3/src/codegen.ts`, `new Function`), the closure skeletons of `compile.ts` staying as the fallback where `new Function` is unavailable (`ZC_V3_CODEGEN=0` forces it; `pnpm run test:v3` fuzzes both). Profiling the closure tree on the S1 account workload (Node 24, `--cpu-prof`) put the object closure at 34% and the array closure at 18% of self time after the cheaper fixes below, with the two format regexes at 21%: every closure instance of one `make*` literal shares a single V8 feedback vector, so the child call site is megamorphic, `data[k]` is a keyed load and nothing is inlined. A generated skeleton has one monomorphic call site per child and named loads, and a leaf whose acceptance is a pure predicate (string bounds and formats, number bounds and `int`, boolean, literal, enum, date, optional / nullable of those) is tested inline and handed to its closure only when the test fails, so the issue is produced exactly as before. Two closure-level changes come with it and stay in the fallback too: the undeclared-key probe of strip / strict objects compares each enumerated key against the shape key expected at that position (one string compare) before consulting the key map, and uses `hasOwnProperty.call`, which V8 folds inside a `for...in` over the enum cache where `Object.hasOwn` is not (163 ns to 25 ns per 10-key object in isolation); a container whose subtree holds no ZodEffects node does no `ctx.path` push/pop on the success path and splices its key into the issues a child left behind instead (`prefixIssues`), while containers above a refine / transform / preprocess stay eager because the callback's `ctx.path` needs the absolute path. Removing the path bookkeeping and the old probe alone took the S1 account from 1 159 to 782 ns; the generated skeletons take it to 308 ns (200 000 rows, local A/B). `safeParse` builds its `ZcError` lazily on first access of `error`, as stock does. - The zod4 object skeleton runs its own-symbol probe in strict and loose mode too, not only in strip mode. Stock zod rebuilds every object and so drops an undeclared own symbol key (enumerable or not) in every mode, and strict mode never rejects one (its unknown-key loop sees string keys only); before this change a clean strict or loose input was returned by reference with the symbol kept, and only a dirty one lost it, a divergence listed under known limitations since #41. Now `compile(schema)` gives stock's output on every path in every mode, at the cost strip mode already paid (one `Object.getOwnPropertySymbols` call, about 36 ns, per clean object; loose mode's clean path had no probe before, strict mode's already ran the unknown-key loop), and `compile(schema, { ownSymbolKeys: "ignore" })` switches the probe off in every mode instead of strip mode alone, so the option now means the same thing for every object. The differential generator emits its extra own symbol in every object mode (it excluded strict and loose before), which made the previous engine fail on 4 of 10 000 cases and the new one on none; at the 20 000-case default the top-level reference sharing among successful cases is 88.8% (default) and 89.4% (`"ignore"`), from 89.2% and 89.6% before, the difference being the strict and loose inputs that now copy as stock does; a new smoke group covers strict and loose objects under both settings (#42).
- The zod4 object skeleton assembles its copy the way the official parser does, from the locals captured during validation: a shape-ordered literal (or `{}` plus the official `mayOutputUndefined` / `dropsWhenAbsent` writes when a key is conditional) and, in loose mode, the undeclared string keys appended by `for...in`. The previous `{ ...input }` spread plus `delete` re-read every getter (#36, fixed), kept the input's key order and left a dictionary-mode object behind, which made the strip case slower than stock zod. Undeclared keys are now dropped by construction, so strip mode runs its two probes (the `for...in` string probe and `Object.getOwnPropertySymbols`) only when no key is dirty; a strip shape declaring only symbol keys now probes for undeclared string keys like any other (#35). The statically dead branches of the tuple template (absent branches of slots the length guard proves present, the gate of the first tail slot) are folded at compile time (a code-size simplification with no measured effect; inlining small leaf tuples into the parent skeleton was measured at no gain on S6 and not kept). The compiled wrapper's methods are specialized per mode (sync skeleton, async skeleton, stock degradation), so a sync `parse` / `safeParse` / `validate` call is one skeleton call plus the result object. ### Added

- zod4 union skeleton (#58): a union with a container option (object / array / tuple / record / map / set, directly, under optional / nullable, or in a nested union) is compiled into a skeleton (`emit-union.ts`) that tries each option's CoW product in stock's order and returns the first non-`INVALID` result, a discriminated union dispatching on its discriminator like stock's codegen, the union's own `.refine` predicates running on the winning value. A clean input is returned by reference by the matching option's skeleton and a dirty option copies only its path to the root, where #55 handed the whole union to the official parser and rebuilt the matching container on every parse. A leaf-only union keeps the validator; `z.xor`, a discriminated union stock's codegen declines (`unionFallback`, an option without static discriminator values, a duplicate value), a union carrying a check other than a refine predicate, and a union with an async option keep the official product. `emitBoxedContainer` ends a wrapper chain at an `optional` layer whose inner is `defaulted` (a union with a defaulted option, the one such inner a chain can now hold) and calls the inner as a nested product on `undefined` too, as stock's `generateOptionalCheck` does (the first skeleton shortcut it; fuzzer seed 145, case 12). Fuzzer sharing rate at the default size 82.5% (default) / 83.3% (`"ignore"`) among successful cases, from 81.7% / 82.4%, 0 degradations, every case agreeing with stock; 82.1% / 82.8% at 50 000 cases. Smoke group 21.
- Smoke group 17 pins the clean-path family of #48 next to its documentation: a non-enumerable undeclared string key survives the clean path of every object mode and every record path (the number-keyed record included) and is dropped by the copy path like stock, a class instance is returned as it is (the copy is a plain object; records reject it on both sides), an inherited enumerable key is copied by strip like stock and kept inherited by loose where stock's `for...in` append writes it as an own key, and a throwing `ownKeys`, `getOwnPropertyDescriptor` or `getPrototypeOf` trap is observed as documented (a `for...in` consults all three, the last while walking the prototype chain; strip throws from its `for...in` probe where stock's strip parses; loose consults `ownKeys` alone by default and nothing under `"ignore"`, where stock consults all three). The object skeleton's `code` is asserted free of explicit descriptor and prototype probes, so adding one is a deliberate change. The README bullet for #48 was corrected on the loose case (since #42 the own-symbol probe consults `ownKeys`, so a throwing `ownKeys` trap throws on both sides by default; the issue's table predates that) and extended with the loose inherited-key variant and the record parity note; `docs/ARCHITECTURE-z4.md` §3.1 gained the anchor. No engine change (#48).
- `compile(schema, options?)` takes an optional `CompileOptions` argument, exported as a type. Its one option, `ownSymbolKeys: "probe" | "ignore"` (default `"probe"`), decides whether an object skeleton runs the `Object.getOwnPropertySymbols` probe before returning the input by reference (strip mode at first; every object mode since #42, see Changed). `"ignore"` skips it at every depth of the tree for callers whose data carries no symbol keys (JSON input, structured-clone output); an input that does carry an undeclared own symbol key is then returned by reference with the symbol kept where stock would drop it, while declared symbol keys, the copy path, `validate()` and the failure path are unchanged. An unknown value throws a `TypeError` from `compile` (`null` included; an explicit `undefined` is an absent property), as does an options argument that is not a plain object (`Object.prototype` or null prototype), and both rejections stay a `TypeError` for an object or value that fights the diagnostic (a throwing `constructor` / `name` accessor, a Proxy whose `getPrototypeOf` trap throws, a `toJSON` method or Proxy `get` trap on the value, a bigint, a cycle), since the message reads descriptors and type tags instead of running the rejected thing's code (no `JSON.stringify`); a throwing accessor or Proxy trap hit while reading the option off the options object surfaces as a `TypeError` with the caller's error as `cause`; only an own `ownSymbolKeys` property is read, so a value inherited from a polluted `Object.prototype` does not turn `compile(schema, {})` into the opt-in. Verified by a new smoke section, by a second pass of the differential fuzzer (the same 20 000 cases compiled with the option against a generator that emits no extra own symbol, with a check that no generated top-level code carries the probe, and a check that the pass shares at least as many references as the default pass), and by the packed-tarball smoke, whose runtime and type consumers use the option. `bench-v4` measures the option as a separate, labelled opt-in row of the calibration section (`z.compile()` and zod-cow-v4 with the option runnable, the other columns `N/A — unchanged from the default row above`, a gate fixture declaring the symbol divergence); the zod-cow-v4 column of every other scenario keeps the default (#43).

## [0.5.0]

Tuple CoW skeleton, async schema support, upstream issue draft.

### Added

- Tuple skeleton, completing the six containers: a line-by-line mirror of the official `generateTupleCheck` with the CoW rewrite applied.
  - `optinStart` / `optoutStart` (official `getTupleOptStart`, copied verbatim) plus the official length guard (`[optinStart, N]` when there is no rest element).
  - A `fillLen` variable: the official template gates trailing slots on the dynamic `out.length`, but under CoW the output may still be the input reference, whose `.length` must not be read or written, so the logical length is tracked explicitly. Invariant: `out === input ⟹ fillLen === input.length`.
  - Three segments: unconditional slots (absent slots keep the official materialization semantics), gated trailing slots with three absent-branches (`dropsWhenAbsent` truncation, validator truncation, IIFE INVALID/undefined truncation, value fill), and ungated rest slots.
  - Three truncation states. If the output is already a copy, truncate in place. If it is still the input reference and the target length differs from the input length, copy, then truncate. If the target length equals the input length, the output stays the input and nothing happens, so short inputs with trailing optionals keep the original reference.
- Async channel: async schemas no longer degrade the whole tree.
  - The six `isAsyncFunction` throw sites in the official `compileFn` are a ready-made async detector: a `ZodCompileAsyncError` turns the subtree into an async island (returns `Promise<out | INVALID>`, product tagged with the `ZC_ASYNC` marker).
  - Every product call site (object keys, array elements, tuple slots, record values, map keys and values, set members, container check predicates) is async-aware, emitting `await` and setting `ctx.async`, so the skeleton becomes an async function and parent skeletons pick it up automatically.

  - Public API: `Compiled.async` flag plus `parseAsync` / `safeParseAsync`; the sync API on an async skeleton throws `$ZodAsyncError`, as stock does.

## [0.3.0]

zc-z4: a CoW layer over zod4's official codegen. This is the design the current zod4 line still follows.

### Motivation

zod4 (>= 4.1) ships a JIT compiler, `src/v4/core/compile.ts`, reachable through the side-effect entry `import "zod/compile"` or an explicit `z.compile()`. It compiles a whole schema tree into a monolithic validation function (`new Function` plus hoisted constants) and exposes two products this layer reuses:

| Official capability | Meaning | Reused as |
|---|---|---|
| `compileFn(schema)`, the parser product | stock semantics (unconditional new containers) | semantic backend for impure subtrees (transform/default/catch/record/union, all official) |
| `compileFn(schema, {assertOnly: true})`, the validator product | validation only, output construction skipped | validation backend for pure leaf keys, and the whole-tree `validate()` fast path |
| `INVALID` sentinel plus runtime fallback | the failure path falls back to the runtime to collect full issues | any failure in this layer returns the sentinel; issues, paths and `ZodError` are 100% official |

The earlier self-written zod4 front-end (v0.2) contained about 1100 lines of semantic codegen. The self-written part of v0.3 shrank to:

1. Purity analysis (about 120 lines, a conservative whitelist) deciding "validation passes ⇒ output must be `===` input". Traps found by fuzzing: `overwrite` checks (`.trim()` / `.toLowerCase()`) rewrite values and are impure; length/size checks carry a default `when` function (the official `WHEN_DEFAULTED_CHECKS` whitelist) and must not be rejected as custom `when`; containers wrapped in `optional` / `nullable` must be unwrapped before classification (checking `def.type` alone sends `nullable(object)` to the official `assertOnly` product and loses strip semantics).
2. Container CoW skeleton codegen (object and array templates, about 200 lines): the official "unconditional new container" (`const out = {...}` / `new Array(n)`) is rewritten into "reference comparison as dirty check plus conditional shallow copy". Clean input does `return input` (the one line the official template lacks); a forced copy does `out = { ...input }`, so key presence and key order are preserved by the spread, and strip detects extra keys with the official `for...in` plus `Set` probe and deletes them on the copy.
3. Container-level checks subroutine (refine/min/max): an independent validation function called on both paths, matching stock semantics (checks run on the final output: the input when clean, the rebuilt `out` when dirty).

### Degradation chain (per subtree, every step keeping stock's results)

```
CoW container skeleton
  ├─ pure leaf → official assertOnly validator (full validation, zero construction)
  ├─ impure subtree → official parser product plus reference comparison
  ├─ product generation failed → runtime island (black-box _zod.run)
  └─ whole tree not compilable (async / recursive top level / schema catchall) → stock safeParse
Every failure path falls back to stock (full issues / error map / ZodError).
Coexists with the global "zod/compile" shim: the fallback path gets the official JIT for free.
```

(v0.5 later replaced the whole-tree degradation for async schemas with async islands.)

Conclusions at the time (how the value proposition changed on zod4):

1. zod4 had already removed most of the "interpreter tax": the same scenario went from 2092 ms on stock zod3 to 223 ms on stock zod4 (9.4x). zod4's parse is a specialized function per type with lazy paths and no per-node context allocation.
2. The CoW closure tree was no longer the speed winner on zod4 (4.3 to 5.0x on zod3, 0.5 to 0.8x on zod4): the allocation saved by not rebuilding the output tree (cheap on V8's bump allocator) did not offset the call overhead of a generic closure tree against zod4's specialized functions. Micro-probes showed the leaf validators were faster (string 1.6x, number 2.4x); the gap was in object assembly, where zod4 classic uses `$ZodObjectJIT` code generation.
3. The structural benefits were unchanged: allocation pressure -99.7%, 0 MB retained after GC (stock constant +108 MB), output `===` input reference (structural sharing, safe aliasing, incremental-update semantics).
4. The `zod4/compile` JIT was level with stock in this scenario; arktype stayed fastest (158 ms).
5. Closing the speed gap meant the `new Function` monolithic codegen proposed in the v0.1 worklog. v0.3 took the shortcut of reusing zod4's own codegen instead.

## [0.1.0]

The zod3 CoW compilation layer: a hand-written closure-tree compiler (`src/compile.ts` + `src/index.ts`) that is now the frozen reference implementation.

### Added

- `compile(schema)` for zod 3.24.1 schemas, returning `parse` / `validate` (a `DeepReadonly` view) / `safeParse` and a static `pure` flag. The schema is consumed as is (the `.def` tree is read); zod is not forked and the Zod API is unchanged.
- Compile-time parsing of shape, keys and checks into specialized validation closures; a single mutable ctx with lazy paths (a path snapshot is materialized only when an issue is produced).
- The CoW invariant: every node is `(data, ctx) => value | FAILED`; primitives compare by value, containers by reference; a parent shallow-copies at the first changed child. Strip never deletes on the input object (the Numeric fork's in-place delete was the footgun this fixes).
- `src/probe.ts`: runtime probes of stock zod3 edge semantics (absent optional keys are not materialized, present-undefined keys are kept, default values pass the inner validation, issues are collected across siblings, readonly freezes shallowly), so the compiler adapts to the installed version.
- String format regexes copied verbatim from zod 3.24.1 into `src/regexes.ts`.
- `ZcNotSupportedError` at compile time for `intersection`, `catchall`, tuple rest, `ZodPromise` and async refine (detected at runtime).

### Verification

- 27 unit tests plus 20 000 differential cases (random schema plus random data, asserting success parity, `deepStrictEqual` outputs and zero input mutation), all passing; top-level reference-sharing rate about 92% on successful cases.
